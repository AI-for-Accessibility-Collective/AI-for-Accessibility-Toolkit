# Building blocks for adapters

Generated by `toolkit/scripts/generate-skill.mjs` with the skill: do not hand-edit. Source: `toolkit/blocks/` (blocks 2026-11-04, prompts 2026-11-03).

The toolkit supplies the parts adapters kept writing for themselves: undoing changes, stylesheets, watching and reading the page, highlighting, announcing to screen readers, tooltips, panels, focus and shortcuts, text changes, AI text and vision, speech, and media. Build on them where one fits. Each has a **config** you set, takes the **person's own settings** from their profile over yours, and keeps **invariants** no config can change, because each was a bug in an adapter that built its own.

The toolkit is a research project in pre-alpha and the blocks are new: check what an adapter built on them does on the page, as with any adapter.

## Using them

In the browser runtime (and the assistant sidebar's previews), `enable(options, toolkit)` gets them on `toolkit`: `toolkit.session()`, `toolkit.page` and `toolkit.personal`, next to `toolkit.data` and `toolkit.observe`. In an app of your own (JavaScript), `import { createBlocks } from '<toolkit>/blocks/index.js'` and call `createBlocks({ win: window, adapter: '<id>', personal, ai })`, where `ai` runs the model (the service's `POST /v1/ai/text` and `/v1/ai/vision` do, with your token).

```javascript
export default {
  enable(options, toolkit) {
    if (this.s && !this.s.ended) return;      // already on
    const s = (this.s = toolkit.session());
    // every change through s: s.setStyle, s.css, s.tooltip, s.highlight, ...
  },
  disable() {
    this.s?.end();                            // undoes everything, in reverse
  },
};
```

- **Everything through the session.** It records each change and `end()` undoes them in reverse, keeping any value the page changed since. After `end()`, every block is a no-op and every AI answer is `null`, so a late answer never changes the page.
- **Config is plain JSON** (and a few callbacks, such as a tooltip's `content`). Leave a value out to get the default.
- **The person's settings win.** What you set is a default: where their profile says how fast speech should be, their reading level, text size or reduced motion, the blocks use that. `toolkit.personal` shows what the profile set.
- **The toolkit's own elements are marked** (`data-ai4a11y-ui`), so the blocks' watchers and text walkers never react to them.

## The person's settings

| Key in `toolkit.personal` | What it is |
|---|---|
| `speechRate` | Speaking rate, 0.5-2. speech.say({ speechRate }) uses the profile's over yours. |
| `fontScale` | Text size in percent, 100-200. Tooltips and panels scale their text by it (their `fontScale`). |
| `textSizeMethod` | 'zoom' (the browser's zoom) or 'font' (the text size only): how the person wants text made bigger. Unset: your default. |
| `lineHeight` | Line spacing, 1-3 (times the font size). |
| `letterSpacing` | Letter spacing in em, 0-0.5. |
| `targetSize` | Smallest size of a clickable control, in CSS pixels, 24-64. |
| `motionReducer` | true when the profile asks for reduced motion. Bands and scrolling stop animating, as with the system setting. |
| `contrastMode` | 'light' or 'yellow-black' when the profile asks for more contrast; 'none' when the person turned it off. |
| `darkMode` | true when the profile asks for a dark theme. |
| `readingLevel` | 'plain', 'easy-read' or a grade 1-12 (the profile's reading level, or plain language). ai.text({ readingLevel }) uses the profile's over yours. |

## The blocks

### Session: reversible changes (`session`)

Every change goes through a session, and disable() is s.end(): it undoes them all, in reverse. Every other block is made from the session.

```javascript
const s = toolkit.session({ restore })
s.setAttr(el, name, value)            // value null removes it
s.setStyle(el, prop, value, priority)
s.addClass(el, ...names)
s.insert(parent, node, before) / s.append(parent, node)
s.replace(oldNode, newNode) / s.remove(node) / s.setText(textNode, text)
s.listen(target, type, fn, options)   // returns a function that removes it
const cancel = s.timer(fn, ms) / s.every(fn, ms) / s.frame(fn)   // each returns a function that cancels it
s.el(tag, { text, attrs })            // a new element marked as the toolkit's own
await s.guard(promise)                // throws Ended if the session ended meanwhile
s.onEnd(fn) / s.alive() / s.ended / s.end()
const mode = s.group()                // a session inside this one: mode.end() undoes only what went through it
```

| Config | Default | What it does |
|---|---|---|
| `restore` | `"unless-changed"` | 'unless-changed' puts a value back only if the page has not changed it since; 'always' puts it back regardless. |

Always, whatever the config:

- end() undoes everything in reverse, is idempotent and never throws.
- After end(), every change and every callback is a no-op: a late answer or timer never writes to the page.
- A value the page changed since the session set it stays as the page set it.
- Setting the same attribute or style property again changes the one record: re-applying on every page change never grows what end() has to undo.
- A group ends with its session. Use one for each mode, or each round of fixes you redo, instead of undoing by hand.

### Styles (`styles`)

Stylesheets the adapter adds, and the one page filter all adapters share.

```javascript
s.css(name, cssText, { scope })       // one <style> per name; scope adds that class to <html> while open
s.css(name, null)                     // takes that <style> away
s.filter(name, value)                 // e.g. s.filter("dim", "brightness(0.85)"); composes with other adapters' filters
```

Always, whatever the config:

- One `<style>` per name.
- Filters from different adapters compose in one chain instead of replacing each other.

### Watch (`watch`)

React to what changes while the adapter runs.

```javascript
s.watch.added(root, (el) => ..., { debounceMs, cap, types, selector })
s.watch.added(root, (els) => ..., { batch: true, debounceMs })   // all of one flush at once: measure them, then change them
s.watch.route((url) => ...)           // the address changed without a page load
s.watch.prefs((p) => ...)             // { motionReducer, moreContrast, darkMode, forcedColors }
s.watch.byPerson(el, { withinMs })    // true if the person just clicked, tapped or typed in el
```

| Config | Default | What it does |
|---|---|---|
| `debounceMs` | `0` | Wait this long after the last change before calling back. |
| `cap` | `500` | At most this many elements per call (per batch); more added at once come in the next calls, none dropped. |
| `types` | `["childList"]` | What to watch: 'childList', 'attributes', 'characterData'. |
| `selector` |  | Only elements matching this (and matches inside added subtrees). |
| `batch` | `false` | Call back once with every element of the flush, instead of once for each: read all their sizes before writing any. |
| `withinMs` | `1000` | byPerson: how recent the click or key must be. |

From the person's profile, over your value:

- `motionReducer`: prefs() reports motionReducer, darkMode and moreContrast as true when the profile asks for them, even if the system does not.

Always, whatever the config:

- Never reacts to the toolkit's own UI or to what a block wrote.
- Stops on end().
- Without a selector you get each element added, not what is inside it (an added list brings its items in, unseen); give a selector to get the controls inside added content too.
- With batch, fn gets an array.

### Page (read-only) (`page`)

What is on the page. toolkit.page and s.page are the same object; nothing in it changes the page.

```javascript
toolkit.page.main()                   // the main content region
toolkit.page.readableText(el, { blockPause, skip })
toolkit.page.textNodes(el, { skip })
toolkit.page.headings({ maxLevel })   // [{ el, level, text }]
toolkit.page.nameOf(el)               // accessible name; never a field's typed value
toolkit.page.find(name, { within })   // the visible control whose name best matches
toolkit.page.isVisible(el) / toolkit.page.isOurs(el)
toolkit.page.background(el) / toolkit.page.contrast(a, b)
toolkit.page.textContrast(el)        // { color, background, ratio, min, large, overImage, fix }
toolkit.page.widgetParts(widget)     // a carousel's slides or a tab set's panels, as ARIA marks them; [] when it does not
toolkit.page.ownControls(widget, { parts })   // its own buttons (pause, next, pick a slide), not those inside its slides
```

| Config | Default | What it does |
|---|---|---|
| `skip` | `""` | More selectors to leave out, on top of code, form fields, live regions, hidden content and the toolkit's UI. |
| `maxLevel` | `6` | headings(): the deepest level to include. |

Always, whatever the config:

- Read-only.
- ownControls() decides from roles and relationships, never from names or classes: a control that names what it controls (aria-controls) is the widget's only when that is the widget, one of its parts or what holds them; one that does not say is the widget's only when it is outside every part. A "Play trailer" button inside a slide is the slide's, not the carousel's.

### Highlight (`highlight`)

Show the person where they are: an element, a stretch of text, a band that follows the pointer, a strong focus ring.

```javascript
const h = s.highlight.element(el, { style, color }); h.move(other); h.clear()
const r = s.highlight.range(range, { color }); r.move(nextRange)   // no change to the page's text
const band = s.highlight.follow({ source, height, dimOutside })
s.highlight.focusRing({ color, width })
```

| Config | Default | What it does |
|---|---|---|
| `style` | `"background"` | 'background', 'outline' or 'underline'. |
| `color` | `"auto"` | 'auto' picks one with enough contrast; a colour you give is used only if it has enough. |
| `width` | `3` | Outline or underline width, in pixels. |
| `source` | `["pointer","focus"]` | follow(): 'pointer', 'focus' or both. |
| `height` | `40` | follow(): band height in pixels. |
| `dimOutside` | `0.4` | follow(): how much to dim above and below the band, 0-0.9; 0 tints the band instead. |
| `ringWidth` | `3` | focusRing(): width in pixels (passed as `width`). |

From the person's profile, over your value:

- `motionReducer`: The band does not animate.

Always, whatever the config:

- A background that would fail 4.5:1 against the text is not drawn; an outline that passes 3:1 is drawn instead.
- Text ranges use the CSS Custom Highlight API: the page's text nodes are never split or wrapped.
- The focus ring shows on any background and beats a page's outline: none !important.

### Targets: room to grow and hit areas (`targets`)

Make controls easier to hit without covering each other: how far each may grow, measured once, and a larger hit area that changes neither how it looks nor where anything is.

```javascript
const room = s.targets.room(els, { size, others, rects, within, still })
// Map el -> { rect, top, right, bottom, left, clipped, lines }: how far to grow on each side
s.targets.hitArea(el, room.get(el), { attrs })   // "pseudo", "ring" or null
s.targets.hitAreas(room, { attrs })             // all at once: Map el -> "pseudo" | "ring" | null
```

| Config | Default | What it does |
|---|---|---|
| `size` | `24` | room(): the smallest size, in CSS pixels, each element should reach in both directions. |
| `others` | `[]` | room(): more targets to keep clear of (measured, not returned). |
| `rects` |  | room(): a Map el -> rect to use instead of measuring: the size an element had before you grew it. |
| `within` |  | room(): the box nothing may grow past (default: the page; the viewport for fixed elements). |
| `still` |  | room(): those of others you never grow (a label whose control is the target): a target may take the whole gap to them, not half. |
| `attrs` |  | hitArea(): attributes for the ring, if one is made (an object, or a function of the element), so you can find it later. |

From the person's profile, over your value:

- `targetSize`: Pass the person's targetSize as room()'s size.

Always, whatever the config:

- room() is the same whatever order elements come in: between two targets each takes at most half the gap when the other grows toward it, the whole gap when the other is already big enough that way (or is one of still). Grown boxes never overlap, and none goes past the page's edge.
- A `<label>` and the control it labels (`label.control`) are one target: neither keeps the other back, so a control may grow over its own label, while other targets keep clear of the label. Pass such labels in others (and still) so that nothing grows over them.
- room() reads the layout once and says what would be cut off by a clipping ancestor (clipped) and how many lines an element has (lines), so nothing is read again after a change.
- hitArea() never changes how the element looks or where anything is: a pseudo-element the page does not use (any content counts, even ""), and position: relative only where it moves nothing else.
- Otherwise a ring around the element, never over it: anchored to it (it follows scrolling and reflow), hidden when the element is scrolled or clipped out of view, and passing presses and clicks on the ring to the element. Where the browser cannot anchor, nothing is made (null).
- A ring is an element inserted right after the element, so page rules that count siblings (:last-child, +, ~, :nth-child) can match differently around it. Prefer a pseudo-element (hitArea() does) and expect this where a ring is the only way.
- hitArea() again on the same element updates the one it made; end() takes all of it away.

### Announce (`announce`)

Tell screen reader users what changed, through one shared live region.

```javascript
s.announce(message, { politeness })   // "polite" (default) or "assertive"
s.announce.batch(key, message, { windowMs })   // many changes, one announcement
```

| Config | Default | What it does |
|---|---|---|
| `politeness` | `"polite"` | 'polite' or 'assertive' (only for what the person must hear at once). |
| `windowMs` | `400` | batch(): how long to gather messages. |

Always, whatever the config:

- One live region per page for all adapters.
- The same message twice is read twice.
- The regions go when the last session that announced ends.

### Tooltip (WCAG 1.4.13) (`tooltip`)

Content on hover or focus: a definition, a link's destination, a title the page hides.

```javascript
s.tooltip({ trigger: 'abbr[title]', content: 'title' })
s.tooltip({ trigger: '.term', content: (el) => s.ai.text('define', el.textContent, { context }) })
const t = s.tooltip(...); t.open(el); t.hide()
```

| Config | Default | What it does |
|---|---|---|
| `trigger` | `"[title]"` | Selector of the elements that show it. |
| `content` | `"title"` | 'title' (the element's title, moved off so the browser's own tooltip does not double it), a string, or a function of the element returning a string, an element, or a promise of one (null shows nothing). |
| `delayMs` | `350` | Hover delay before it opens. Focus opens it at once. |
| `hideDelayMs` | `150` | Grace time to move the pointer onto it. |
| `placement` | `"below"` | 'below' or 'above'; it flips when there is no room. |
| `describe` | `true` | Point the trigger's aria-describedby at it while open. |
| `maxWidth` | `320` | Pixels. |
| `theme` | `"dark"` | 'dark' or 'light'. |
| `fontScale` | `100` | Text size in percent, of 16px (12pt); it never goes below 100. |

From the person's profile, over your value:

- `fontScale`: The profile's text size wins over yours.

Always, whatever the config:

- Its text is at least 16px (12pt), scaled up by the person's text size.
- It can be hovered without closing.
- Escape closes it, and it stays closed while the pointer or focus stays on that trigger.
- It stays open while its trigger has focus.
- A click never closes it.
- A late answer never opens it after it was closed or moved on.
- It never covers the focused element.

### Panel (`panel`)

A dialog, a disclosure region or a full-screen view, with its own Close button.

```javascript
const p = s.panel({ kind: 'dialog', label: 'Chart data', near: chart })
p.body.append(content); p.open(button); p.close(); p.isOpen
```

| Config | Default | What it does |
|---|---|---|
| `kind` | `"dialog"` | 'dialog', 'disclosure' or 'fullscreen'. |
| `label` | `"Panel"` | Its heading, and its accessible name. |
| `near` |  | An element to sit beside (never over it). Otherwise a corner. |
| `corner` | `"bottom-right"` | 'bottom-right', 'bottom-left', 'top-right' or 'top-left'. |
| `focus` | `"from-trigger"` | 'from-trigger' (focus moves in when open() is given what opened it), 'always' or 'never'. |
| `returnTo` |  | Where focus goes on close, if it was inside. By default whatever opened it. |
| `inert` | `false` | fullscreen: make the rest of the page unreachable while open (live regions stay reachable). |
| `theme` | `"page"` | 'page' (the page's font), 'light' or 'dark'. |
| `width` | `360` | Pixels (not fullscreen). |
| `zIndex` | `2147483646` | Stacking order. |
| `fontScale` | `100` | Text size in percent. |

From the person's profile, over your value:

- `fontScale`: The profile's text size wins over yours.

Always, whatever the config:

- A visible Close button at least 24 pixels.
- Escape closes it.
- It takes focus only when its focus policy says so.
- On close, focus returns only if it was inside.
- Placed near an element, it never covers it.

### Focus and keys (`focus`)

Move focus without losing it, and say what the person's shortcut adjusts when they give it to your adapter.

```javascript
s.focus.region(el)                    // focus a region that is not focusable itself
s.focus.keepWhenRemoving(el)          // before el goes, move focus out of it
s.focus.entry({ label: 'Page outline', onActivate: () => panel.open() })   // a button first in the tab order
s.focus.skipLink()                    // 'Skip to main content', unless the page has one that works
s.focus.keepVisible()                 // the focused element is never hidden under a fixed or sticky bar
s.keys.adjust({ label: 'Text size', settings: ['fontScale'], up: () => ..., down: () => ... })
```

| Config | Default | What it does |
|---|---|---|
| `label` |  | adjust(): what up and down change, for the person choosing their shortcut ('Text size'). |
| `settings` | `[]` | adjust(): the person's settings it changes, so they can use this site's values on every site from the extension. |

From the person's profile, over your value:

- `motionReducer`: region() scrolls without animation.

Always, whatever the config:

- Adapters have no shortcuts of their own. The toolkit has one pair of keys, off until the person gives it to one adapter: with keys.adjust, up and down adjust; without (or while it is off on the site), the first key turns it on and off on this site.
- up() and down() count as the person's own key, so they may call profile.set; they never fire in a text field or editable region.
- The temporary tabindex region() adds goes when focus leaves.
- entry() and skipLink() are the toolkit's own controls at the start of the tab order, after the page's own skip link, in one place for every adapter. Each is out of sight until it has focus, then shown at the top left, so it covers nothing. skipLink() adds nothing (null) where the page already has a skip link whose target is there, or no main content to skip to.
- keepVisible() (WCAG 2.4.11) measures what is fixed or stuck at the top and bottom of the window where focus is, sets the page's scroll padding to clear it, and scrolls the focused element out from under it once. It never moves focus or changes the tab order.

### Text (`text`)

Change the page's text and get it back: wrap words, change text in place, or show new text in place of a block.

```javascript
s.text.wrap(root, { match: /\b[A-Za-z]{9,}\b/, build: (word) => span, cap })   // returns how many
s.text.set(textNode, text)           // in place, for translation
const r = s.text.replaceBlock(paragraph, newText, { label })   // with a Show original button
s.text.nodes(root)                    // the text nodes it would change
s.text.scale(1.5)                     // the page's text at 150%, px-sized too; 1 puts it back
s.text.fit(() => s.css('spacing', rules))   // change text; grow only the boxes the change now cuts off
const sp = s.group(); sp.text.fit(() => sp.css('spacing', rules)); ... sp.end()   // a setting the person can turn off: its own group, so end() takes the sheet and the boxes fit grew
```

| Config | Default | What it does |
|---|---|---|
| `cap` | `500` | wrap(): at most this many matches. |
| `skip` | `""` | wrap(): more selectors to leave alone. |
| `match` |  | wrap(): a regular expression, or its source as a string. |
| `showOriginal` | `true` | replaceBlock(): a button to see the original. |
| `label` | `"Simplified"` | replaceBlock(): what the new text is. |
| `originalLabel` | `"Show original"` | replaceBlock(): the button while the new text shows. |
| `replacedLabel` | `"Show simplified"` | replaceBlock(): the button while the original shows. |

Always, whatever the config:

- The original text nodes come back on end(), the same objects.
- Code, form fields, live regions, hidden content and the toolkit's UI are never changed.
- A replaced block can always be seen as it was.
- scale() is the text size alone, for when s.zoom.method() is not 'zoom'. It measures before it writes and sizes each element from its own original size, so a new factor never compounds. Pixel line heights keep their proportion; the person's line spacing still wins. A fixed-height box that would cut its text off grows. Text added later is sized as it arrives; the page is measured again when the window's width changes.
- fit() measures the boxes around the page's text, runs your change, and grows only those it made cut text off; a box that cut text off before, by the page's design, stays. Use it for spacing, instead of reading every element's height yourself.

### AI text: simplify, summarize, define, translate, label (`ai.text`)

Ask the toolkit's model for text, with its default prompt for the task adapted by your fields. The service runs the model and checks the answer; you get a string or null.

```javascript
const plain = await s.ai.text('simplify', text, { context, keep: ['Medicare'], tone: 'friendly' })
const meaning = await s.ai.text('define', word, { context: sentence, maxChars: 200 })
const es = await s.ai.text('translate', text, { translateTo: 'Spanish' })
const name = await s.ai.text('label', 'icon button, search form, magnifier icon')
s.ai.available                       // false where no model is wired (then every call is null)
```

| Config | Default | What it does |
|---|---|---|
| `budget` | `40` | Calls per session (cached answers are free). |
| `maxInputChars` | `6000` | Longer input gets null, not a cut: send one block at a time. |
| `fields` |  | The prompt fields (readingLevel, translateTo, language, tone, audience, context, keep, glossary, instructions, template, maxSentences, maxChars, minRatio, maxRatio): see "Prompts" below. |

From the person's profile, over your value:

- `readingLevel`: The profile's reading level (or plain language) wins over yours.

Always, whatever the config:

- The page text is fenced and marked as content, never instructions; the output contract (only the answer) is always added.
- Every answer is checked before you get it: refusals, guesses and answers of the wrong length come back as null.
- null leaves the page as it was. After end(), every answer is null.
- keep (at most 50 terms of 80 characters) and glossary (at most 30) are cut to fit, never refused: gather them from the page freely.

### AI vision: describe an image, read a chart (`ai.vision`)

Describe an element as it looks: an image, a canvas, an SVG, or a chart. The page draws it when it can; otherwise the browser captures it from the screen (it must be in view).

```javascript
const alt = await s.ai.vision('describe', img, { purpose: 'alt' })
const summary = await s.ai.vision('chart', chartEl, { about: heading.textContent })
```

| Config | Default | What it does |
|---|---|---|
| `purpose` | `"alt"` | describe: 'alt' (one sentence) or 'long'. |
| `about` | `""` | Text from the page about the image (a caption, a heading). |
| `maxChars` |  | At most this many characters (default 150 for alt, 1200 for a chart). |

Always, whatever the config:

- As ai.text: checked answers, null on any doubt, nothing after end().

### Speech: speak (`speech.out`)

Read text aloud, with word-by-word events for highlighting. In the browser runtime it speaks with the browser's own speech (the voices the person set up), elsewhere with the page's.

```javascript
const r = s.speech.say(elementOrText, { speechRate, voice, lang, onWord: (range) => h.move(range), onChunk })
s.speech.say(win.getSelection())      // or a Range: what the person selected, with onWord ranges in the page
r.pause(); r.resume(); r.stop(); await r.done; r.speaking
s.speech.say(el, { from })            // start at an offset onWord gave (onWord(range, offset)): a new rate goes on from that word
```

| Config | Default | What it does |
|---|---|---|
| `speechRate` | `1` | 0.5-2. |
| `pitch` | `1` | 0-2. |
| `voice` |  | A voice name (speechSynthesis.getVoices() in a page; the browser's voices in the runtime). |
| `lang` |  | e.g. 'en-GB'. By default the page's language. |
| `chunkChars` | `220` | Longest piece spoken at once (browsers cut long ones off). |
| `waitForGesture` | `true` | Wait for the person's first click or key in the page. |

From the person's profile, over your value:

- `speechRate`: The profile's speaking rate wins over yours.

Always, whatever the config:

- One voice at a time, page-wide: a new say() stops the last.
- Escape always stops it.
- It never starts before the person has used the page.

Listen for spoken commands.

```javascript
const l = s.speech.listen({ commands: { 'scroll down': () => scrollBy(0, 400), 'click *': (name) => s.page.find(name)?.click() } })
l.stop(); l.listening
```

| Config | Default | What it does |
|---|---|---|
| `lang` |  | e.g. 'en-US'. By default the page's language. |
| `feedback` | `"announce"` | 'announce' says what it heard when nothing matched; 'none' stays quiet. |
| `maxErrors` | `3` | Stop after this many errors in a row. |

Always, whatever the config:

- A visible indicator with a Stop button shows while the microphone is on.
- It stops after repeated errors and says why.

### Media (`media`)

Pause, mute and caption audio and video, and leave them as the person left them.

```javascript
s.media.pause(video, { showControls }) / s.media.pauseAll(root)
s.media.mute(el)
s.media.captions(video, { lang })      // show the captions track it already has
```

| Config | Default | What it does |
|---|---|---|
| `showControls` | `false` | pause(): show the browser's controls while paused. |

Always, whatever the config:

- end() never starts what the person paused or played themselves.
- It never re-mutes what the person unmuted.
- It never touches the page's own play() promise.
- captions() never changes a track the page or the person turned on. Call it again when a track is added: it moves its own choice to one in the person's language.

### The person's settings (`profile`)

Read the person's settings on this site, and record a change they make in your adapter, for this site or every site.

```javascript
s.profile.get() / s.profile.get('fontScale')   // = toolkit.personal, kept current
await s.profile.set({ fontScale: 150 })                    // this site (the default)
await s.profile.set({ fontScale: 150 }, { scope: 'all' })  // every site
s.profile.onChange((personal, changed) => ...)
```

| Config | Default | What it does |
|---|---|---|
| `scope` | `"site"` | set(): 'site' records it for this site; 'all' for every site (and drops this site's own value, so it follows). |

From the person's profile, over your value:

- `speechRate`: Settable.
- `fontScale`: Settable.
- `textSizeMethod`: Settable.
- `lineHeight`: Settable.
- `letterSpacing`: Settable.
- `targetSize`: Settable.
- `motionReducer`: Settable.
- `contrastMode`: Settable.
- `darkMode`: Settable.

Always, whatever the config:

- Only the person changes their profile: set() works only right after their own click, tap or key on the toolkit's UI in this page or their shortcut (keys.adjust); otherwise it returns { applied: false, reason: 'not-by-person' }.
- set() calls every onChange listener, your own included, before it returns: apply the change in onChange, and do not apply it again after set().
- Only settings, checked and kept in range: speechRate, fontScale, textSizeMethod, lineHeight, letterSpacing, targetSize, motionReducer, contrastMode, darkMode.
- The change applies in this page at once, for every adapter, and is saved to the profile where the host can ({ saved }).
- What the person set for a site wins over what they set for every site, which wins over what the toolkit derived from their needs.

### Browser zoom (`zoom`)

Zoom the page with the browser's own zoom, which reflows it like the person's own zoom; and whether to zoom or change the text size.

```javascript
const method = s.zoom.method('zoom')   // 'zoom' | 'font': the person's textSizeMethod, else yours
if (method === 'zoom') await s.zoom.set(1.5); else s.css('text-size', '...')   // never both
await s.zoom.get()   // the zoom now, or null
s.zoom.supported
```

| Config | Default | What it does |
|---|---|---|
| `method` | `"zoom"` | method(builderDefault): your default when the person has not chosen; 'font' where zoom is not offered. |

From the person's profile, over your value:

- `textSizeMethod`: The person's choice of zoom or text size wins over yours.

Always, whatever the config:

- Only in the browser runtime (the browser keeps zoom per site); elsewhere supported is false and method() answers 'font'.
- end() puts back the zoom from before, unless the person changed it meanwhile.
- Zoom or text size, never both: method() gives one answer.

## Prompts (`s.ai.text`, `s.ai.vision`)

Each task has the toolkit's own prompt, written to its language rules (plain language; barriers are in pages, not in people). You adapt it with the fields below rather than writing a prompt. Whatever you set, the page text is fenced and marked as content (a page cannot instruct the model), the answer must be only the answer, and the toolkit checks it before you get it: a refusal, a guess or an answer of the wrong length is `null`.

| Task | Call | Input | What it gives |
|---|---|---|---|
| `simplify` | `s.ai.text` | a passage | Rewrite a passage in plain language, keeping every fact. |
| `summarize` | `s.ai.text` | a passage | A short summary of a passage: the main point and anything the reader must do. |
| `define` | `s.ai.text` | a word or phrase (put the sentence it is in into context) | What a word or phrase means here, in one or two plain sentences. |
| `translate` | `s.ai.text` | a passage | Translate a passage into `translateTo`, keeping names, numbers and links. |
| `rewrite` | `s.ai.text` | a passage | Rewrite a passage the way `instructions` say. |
| `label` | `s.ai.text` | what is known about the control: its type, its current text, nearby text | A short accessible name (1-4 words) for a control. |
| `linkText` | `s.ai.text` | the link's text, its address and the sentence around it | Link text (2-8 words) that says where a link goes. |
| `columnHeader` | `s.ai.text` | the column's cells, one per line | A short header (1-4 words) for a table column. |
| `describe` | `s.ai.vision` | an image of the element | Describe an image for a person who cannot see it (alt text, or a longer description). |
| `chart` | `s.ai.vision` | an image of a chart | Describe a chart: its type, axes, trend, and the highest and lowest values. |

| Field | What it does |
|---|---|
| `readingLevel` | 'plain', 'easy-read', or a school grade from 1 to 12. From the person's profile when it has one. (personal) |
| `translateTo` | translate: the language to translate into, e.g. 'Spanish' (the settings vocabulary's translateTo). |
| `language` | The language to answer in, e.g. 'Spanish'. By default the language of the text. |
| `tone` | e.g. 'friendly', 'formal', 'calm'. By default the tone of the original. |
| `audience` | Who reads the answer, in a phrase, e.g. 'visitors new to banking terms'. Describe what they need, not a condition. |
| `context` | What the model needs to understand the text: the page title, the heading, the sentence around a word, the site. |
| `keep` | Terms to keep exactly as written: names, drug names, product codes. |
| `glossary` | { term: explanation } for terms the answer should explain your way. |
| `instructions` | Anything else, in a few plain sentences: "Use British spelling." "Explain each step as a numbered list." |
| `template` | A whole prompt of your own instead of the default. Must contain {text}; can use {context}, {readingLevel}, {language}, {translateTo}, {tone}, {audience}, {keep}, {glossary}, {instructions}, {maxSentences}, {maxChars}. |
| `maxSentences` | At most this many sentences (summarize, define). |
| `maxChars` | At most this many characters (define, label, describe, chart). |
| `purpose` | describe: 'alt' is one sentence for alt text, 'long' a fuller description. |
| `minRatio` | Reject a rewrite shorter than this share of the input (gate). |
| `maxRatio` | Reject a rewrite longer than this many times the input (gate). |

Fields marked personal come from the person's profile when it has them, over yours.

## Example

```javascript
// Plain words: shows each long paragraph in plain language, with a button
// to see the original. Uses the toolkit's building blocks.
export default {
  async enable(options, toolkit) {
    if (this.s && !this.s.ended) return;
    const s = (this.s = toolkit.session());
    if (!s.ai.available) return false;
    const main = toolkit.page.main();
    let done = 0;
    for (const p of main.querySelectorAll('p')) {
      const text = p.textContent.trim();
      if (text.length < 300) continue;
      const plain = await s.ai.text('simplify', text, {
        context: document.title,
        keep: options.keep || [],
      });
      if (plain && s.text.replaceBlock(p, plain)) done++;
    }
    if (done) s.announce(done + ' paragraphs in plain language.');
    return done > 0;
  },
  disable() {
    this.s?.end();
  },
};
```

## Trying an adapter outside the browser runtime

Load the bundle the runtime injects, `extension/vendor/blocks.js`, into the page before the adapter (with Playwright: `await page.addScriptTag({ path })`), then `const toolkit = window.__ai4a11yBlocks.create({ adapter: 'test' })` and `adapter.enable(options, toolkit)`. There every AI call is `null` unless you pass `ai`: an adapter must work, or say it cannot (`return false`), without an answer.
